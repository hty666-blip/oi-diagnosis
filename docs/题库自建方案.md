# 题库自建方案：AI 出题 + 程序证明 + 人审

| 项目 | 内容 |
|---|---|
| 版本 | v1.0 |
| 目标 | 用 AI 生产 **20~40 道 A/B 级题包**（有 validator、有标程、有测试点） |
| 前提 | 爬来的 26 道题只有题面（`package_level: C`），跑不了对拍/最小化 |
| 关联 | [系统架构设计 §9.6 题目包规范](系统架构设计.md) · [题库与数据源调研](题库与数据源调研.md) |

---

## 0. 结论：能，但不能"让 AI 生成完直接入库"

**AI 只负责"写得像一道题"；程序负责"证明这道题是对的"；人负责"这题值不值得留"。**

三者的边界一旦混淆，就会出这种事：

| 事故 | 后果 |
|---|---|
| AI 写的样例和题面矛盾 | 学生样例都过不了，直接怀疑系统 |
| AI 写的 std 本身是错的 | 诊断把正确代码判成错，"证据"变成伪证 |
| validator 漏判（没禁负数/前导零） | 最小化产出非法输入，教学价值归零 |
| 题目有多解但没写 SPJ | 正确解法被判 WA，系统信誉崩塌 |

所以流程必须是：**生成（AI）→ 证明（程序）→ 判断（人）**，且每一步都有产物、可追溯。

## 1. 核心思路：题库 = 错因探针集合，不是题目堆

不要想"攒 1000 道题"。要设计 **20~40 个探针**，每个探针**定向触发一类错因**——这样评测集才有分层，诊断准确率才能按错因统计。

| 探针 | 埋的坑 | 数据特征 | 期望触发的 M 编码 |
|---|---|---|---|
| **P-OVF** 求和 | 答案超过 `int`，但中间变量也超 | `n=1e5, a_i=1e9` | M01 |
| **P-OVF2** 乘法 | `a*b` 溢出，写题面时"看起来"不会 | `a,b ≤ 1e9` | M01 |
| **P-ARR** 数组开小 | 题面 `n ≤ 1e5`，学生习惯开 1e4 | 最大点 `n=1e5` | M02 |
| **P-MULTI** 多测清空 | T 组数据，全局数组不清空 | `T=10`，组间差异大 | M02 |
| **P-EDGE0** 空/单元素 | `n=1`、`n=0`、空串 | 最小点 | M04 |
| **P-NEG** 负数 | 有负数但学生当正数处理 | 含负值 | M04 |
| **P-INF** 死循环 | 循环条件写反 / 递归无终止 | 特殊输入触发 | M05 |
| **P-TLE** 复杂度 | `n=1e5`，暴力 O(n²) 必超时 | 最大点 | M06 |
| **P-CONST** 常数 | 正解但 `cin` 未解绑 + 大量 IO | 大数据 | M06 |
| **P-MOD** 取模 | 负数取模、忘记取模 | 含负值 | M07 |
| **P-PREC** 精度 | 浮点比较、整除方向 | 边界小数 | M07 |
| **P-INPUT** 读入 | 多测格式、空格/换行混排 | 特殊格式 | M08 |
| **P-MODEL** 模型 | 贪心不成立（反例存在） | 精心构造的反例 | M09 |
| **P-BS** 二分边界 | `while(l<r)` 的 `mid` 更新错 | 边界值 | M10 |
| **P-CMP** 比较器 | `sort` 比较器写 `<=` | 有相等元素 | M10 |
| **P-INIT** 初始化 | DP 初值错 / 未初始化 | 小数据即暴露 | M03 |

> **这张表就是你的"题目需求文档"**。20 道题覆盖 11 类错因，比 100 道随机题有用得多。
> 答辩时可以直接说："题库是按错因编码反向设计的，每道题对应一个可验证的诊断假设。"

## 2. 五步流水线

```
① 选题（人/规则）      ── 从探针矩阵挑一个格子
        ↓
② 出题面（AI）        ── statement + 约束 + 样例 + 标签（JSON）
        ↓
③ 出解（AI）          ── std.cpp / brute.cpp / gen.py / validator.cpp
        ↓
④ 证明（程序）        ── 四道闸门（见 §3），任一失败即打回 ②③
        ↓
⑤ 审题（人，5 分钟）  ── 歧义？难度？样例够不够暴露坑？
        ↓
⑥ 入库                ── 标记 ai_generated + 验证报告 + 审题人
```

**返工是常态**：AI 一次过的概率约 40%，加上验证反馈重试 1~2 次可到 80%。

## 3. 证明：四道闸门（最关键的一节）

### G1 · validator 自检

| 检查 | 方法 | 通过标准 |
|---|---|---|
| 正样本 | `gen.py` 生成 200 组随机数据，全部喂给 validator | 100% 通过 |
| 负样本 | 手工构造 10 组非法数据（越界、负数、格式错、少行） | **必须全部被拒** |

> 只测正样本的 validator 等于没测。**负样本才是它的价值所在**。

### G2 · 对拍（防"标程也错"）

```
for i in 1..500:
    data = gen.py(small params)     # 小数据，brute 跑得动
    assert std(data) == brute(data)
```

**必须让 std 与 brute 用不同算法**（如 O(n log n) vs O(n²)），否则"同错"无法被发现。

### G3 · 边界集

人工列 6 类，缺一不可：

| 类型 | 例子 |
|---|---|
| 最小 | `n=1`、唯一的元素 |
| 最大 | `n=1e5`、值取上界 |
| 全相同 | 所有元素相等（打比较器/去重） |
| 含 0 | 0 作为值 / 长度为 0 |
| 含负 | 负数（打取模/绝对值） |
| 极值组合 | 最大 n + 最大值（打溢出 + 复杂度） |

### G4 · 多解检测

如果题目存在多组合法输出（如"输出任意一组解"），**必须写 checker（SPJ）**，否则判题会误杀。

判断方法：让 AI 自己回答"这道题是否存在多解"，再用两个不同策略生成输出对比。

### 附加 · 时限标定

在目标判题机（go-judge 容器）上跑 std 的最大数据，取 `实测时间 × 3` 作为 `time_limit_ms`（不低于 1000ms）。

## 4. AI 出题的 Prompt 模板

> 放在 `prompts/problem_gen/`，版本化。以下为核心结构，可直接用。

### 4.1 出题面

```
你是信息学竞赛出题人。请生成一道{difficulty}难度的题，严格满足：
- 知识点：{knowledge_point}
- 必须能触发错因：{target_error}（{error_description}）
- 数据范围要让 {target_error} 自然发生（不要提示学生）
- 题面必须包含：背景（≤2句）、任务、输入格式、输出格式、数据范围、1~2 组样例
- 样例必须能用手算验证，且不能暴露坑

输出 JSON：
{"title","statement_md","input_format","output_format",
 "constraints":{"n_max":...,"value_max":...},
 "samples":[{"input","output"}],"tags":[...],"solution_sketch":"..."}
```

### 4.2 出解

```
基于以下题面，生成四个文件：
1. std.cpp      —— O({expected_complexity}) 正解，必须处理所有边界
2. brute.cpp    —— 暴力解，算法必须与 std 不同（用于对拍）
3. gen.py       —— 数据生成器，接受 seed 和 mode(small/large/edge)
4. validator.cpp—— 输入校验器（不依赖 testlib，纯 C++ 读入并检查格式与范围）

要求：
- std 与 brute 必须能对拍（相同输入 → 相同输出）
- validator 必须拒绝：越界、负数（若不允许）、格式错误、行数不足
- 所有代码必须能在 -O2 -std=c++17 下编译
```

> 用"纯 C++ validator"而不是 testlib，是为了**零依赖**、能在任何环境下编译；等环境稳定后再换 testlib。

### 4.3 自我批判（审题）

```
你是审题人。找出以下题目的问题，逐条列出：
1. 题面歧义（同一句话能否有两种理解）
2. 样例与约束是否矛盾
3. 是否存在多解而未说明
4. 数据范围是否让 std 超时
5. 目标错因是否真的会被触发（给出一段"典型错误代码"并说明它会错在哪）
只输出问题清单；没有问题则输出 "PASS"。
```

第三条最关键：让 AI **写一段"学生会怎么写错"**，如果它写不出来，说明这个坑埋得不自然。

## 5. 闭环：用系统自己验证题目

题包做完后，丢进诊断系统跑一遍：

```
std.cpp 当作"学生代码" → 应得 AC
故意写一个含 M01 的错解 → 系统应诊断出 M01
```

- **能**验证：题包内部一致、诊断链路通、错因标签正确；
- **不能**验证：题意本身是否清晰（这只能靠人）。

> 注意别形成循环论证：如果 std 和 brute 都错，系统也会"确认"错误答案。所以 §3 的 G3（人工边界）不可省。

## 6. 失败模式与对策

| 现象 | 根因 | 检测 | 修复 |
|---|---|---|---|
| 学生样例都过不了 | 样例与题面矛盾 | G1 正样本 | 重生成样例 |
| std 超时 | 复杂度与约束不匹配 | 时限标定 | 降约束或换算法 |
| 所有人都 AC | 数据太弱 | 用"典型错解"跑一遍，应 WA | 加针对性数据 |
| 最小化产出非法输入 | validator 漏判 | G1 负样本 | 补规则 |
| 正确解被判错 | 多解无 SPJ | G4 | 写 checker |
| 题目"一眼模板" | AI 生成同质化 | 人工审题 | 换场景/加包装 |

## 7. 工作量估算（20 道探针题）

| 阶段 | 单题耗时 | 20 题合计 |
|---|---|---|
| 出题面 + 出解（含重试） | ~10 min | 3.5 h |
| 程序证明（跑闸门、修） | ~15 min | 5 h |
| 人工审题 | ~10 min | 3.5 h |
| 入库与标签 | ~2 min | 0.7 h |
| **合计** | | **≈ 13 小时**（分 3 天做完） |

对比：手写 20 道题 ≈ 20~25 小时。**AI 省一半，但省不掉"验证"那 5 小时**——而验证恰恰是毕设里最值钱的部分（可写进论文的"数据质量保障"章节）。

## 8. 落到数据结构

```yaml
# problems/<pid>/meta.yaml
id: PTV-0001
title: 区间求和
difficulty: 普及−
knowledge_points: ["前缀和", "整数溢出"]
target_errors: ["M01"]          # 这道题是哪个错因的探针
package_level: A                # A=有数据+validator+std
time_limit_ms: 1000
memory_limit_mb: 256
source: ai-generated
ai_generated: true
model: <model-id>
generated_at: 2026-11-02
verified:
  validator_positive: 200/200
  validator_negative: 10/10
  stress_pairs: 500
  edge_cases: 6
  checker: none
reviewer: <你的名字>
reviewed_at: 2026-11-02
license: 自建，CC BY-SA 4.0（可对外分发）
```

配合校验脚本 `tools/check_package.py`（结构完整性 + 元数据合法性 + 与探针矩阵的一致性），在入库前跑一遍。

```bash
python tools/check_package.py --dir problems
# 题包    级别  测试点  错因探针  状态
# PTV-0001  A     3     M01      OK
# 错因覆盖: 1/11  未覆盖: ['M02', ...]
```

仓库里已附一个可直接跑通的示例：`problems/PTV-0001/`（求和 / M01 溢出探针，含 `std/brute/validator/gen` 与 3 组测试点）。

## 9. 一句话给答辩

> **题库不是"找来的"，是"设计出来的"**：按错因编码反向设计探针，用 AI 生产草稿，用程序证明正确性，用人判断教学价值。这样每一道题都对应一个可验证的诊断假设，而不是一堆随机题目。
