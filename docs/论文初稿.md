# 证据驱动的多 Agent 青少年信息学错题诊断系统设计与实现

> **论文初稿 v0.1**（2026-10-29）
> 说明：本文所有实验数据均来自 `eval/reports/` 下的实测记录；引用文献见 §7，标注「待核实」的条目提交前需复核。

---

## 摘要

青少年信息学竞赛的初学者在提交代码后，通常只能得到 `Wrong Answer` 一类的判定结果，而"为什么错、错在哪、该怎么改"需要教练逐题面批。现有大语言模型虽然能讲解题目，却存在三类问题：会给出错误结论、会直接输出可提交的完整代码、缺少可核验的依据。

本文设计并实现了一个证据驱动的多 Agent 错题诊断系统。系统将"错因"拆解为**机制轴**（11 类技术根因）与**性质轴**（6 档教学严重度）两个正交维度，并把诊断流程实现为"分诊—取证—诊断—评审—教学"的确定性状态机。为保证结论可核验，系统要求每条机制层结论必须绑定可复现的证据编号，该约束由类型系统强制而非提示词约定；模型仅被用于规则无法判定的场景，且置信度上限被限制为 0.6、结论一律转入人工复核队列。

系统在 200 条分诊样本上取得 100% 的档位与路由准确率；在 5 个错解的测试中，反例最小化将平均 1800 行的输入缩减至 2.0 行（缩减 99.9%），validator 合法率 100%；在 150 条端到端构造样本上取得 100% 的判定与路由准确率，WA 类叙述关键词命中率 81.7%。消融实验表明：关闭模型后，规则路径在 59 ms 内完成、成本为零，但对需要语义推断的 WA 场景路由准确率为 0%；引入模型后该指标提升至 100%，平均时延增至 630 ms。结果说明两类方法边界清晰、互为补充。

**关键词**：信息学竞赛；错题诊断；多 Agent；程序修复；证据可验证；教学反馈

## 1 绪论

### 1.1 研究背景

信息学竞赛（以 CCF 主办的 CSP-J/S、NOIP 等系列活动为代表）已成为中学生重要的算法能力训练途径。与一般编程学习相比，竞赛训练有三个特点：知识体系强依赖（图论前需掌握搜索与基础数据结构）、反馈周期长（一次机试可产生数道错题，但真正弄懂常需数日）、个体差异大而群体规律强（同一班级的错因高度集中在十余类）。

与此同时，教练资源严重不足。一名教练通常需要面对数十名学生，逐题面批的时间成本使其难以覆盖全部错题；学生得到的反馈因此退化为在线评测系统（OJ）给出的一个判定词。

### 1.2 问题定义

本文关注的核心问题不是"如何生成正确解法"，而是：

> 给定学生的一次失败提交，如何给出**可核验、可教学、可追踪**的错因解释？

现有方案的不足可以概括为三点：

1. **OJ 只给结论**。`WA on test #7` 不解释原因，也不针对学生代码；
2. **题解面向已会者**。题解给出的是正确做法，而非"你的代码为什么错"；
3. **通用大模型不可靠**。模型可能给出错误算法、直接输出完整代码（代做）、语言不适龄，且结论没有证据支撑，无法审计。

### 1.3 本文工作

针对上述问题，本文完成以下工作：

1. **提出机制 × 性质双轴错因模型**。机制轴回答"错在哪个技术点"，性质轴回答"错有多深、该由谁处理"，两轴正交，同一机制码在不同性质档位对应不同教学动作。
2. **设计证据闸门机制**。将"结论必须绑定证据"从提示词约束改为类型系统约束：缺少证据引用的结论对象无法被构造，从结构上阻断无依据的断言。
3. **实现反例最小化流水线**。基于 delta debugging 与题目 validator，把大规模失败输入缩减至学生可手算的规模，为讲解提供可直接使用的教学素材。
4. **构建规则优先、模型兜底的分诊架构**，并通过消融实验量化两者的适用边界。

### 1.4 论文组织

第 2 章综述相关工作；第 3 章给出系统设计；第 4 章说明关键技术实现；第 5 章报告实验；第 6 章总结并讨论局限。

## 2 相关工作

### 2.1 自动程序修复

以 SWE-agent 为代表的工作提出了"Agent-计算机接口"的设计，让模型通过工具与环境交互完成缺陷修复；Agentless 则反其道而行，用"定位—修复—验证"的三段式流水线在较低成本下取得有竞争力的结果；Reflexion 引入语言化的自我反思与情节记忆，使模型能从失败中改进。这类工作与本文的共同点是"以执行反馈驱动修正"，区别在于：修复的目标是产出补丁，而本文的目标是产出**面向学习者的解释**，因此更强调证据的可读性与教学适配。

### 2.2 教育场景的编程助手

CodeAid 在课堂部署中验证了"不直接给答案"的交互设计对学习者的价值；EduChat 则从中文教育对话的角度构建了领域模型。二者为本文的提示策略提供了直接借鉴，但均未解决"如何证明系统说的是对的"这一问题。

### 2.3 知识追踪

贝叶斯知识追踪（BKT）以四参数模型估计学习者对知识点的掌握概率，深度知识追踪（DKT）则用循环网络建模序列。本文采用 BKT 的简化形式，并在状态中显式保留不确定度，以便区分"确实没掌握"与"观测太少"。

### 2.4 差距分析

现有研究覆盖了"修复"与"教学交互"，但缺少面向信息学竞赛的**错因本体**与**可验证诊断链路**。本文的工作正是补上这一层。

## 3 系统设计

### 3.1 总体架构

系统采用模块化单体架构，自上而下分为六层：

| 层 | 职责 |
|---|---|
| 接入层 | Web 前端、REST 接口、SSE 进度推送 |
| 应用层 | 提交、诊断、答疑、报表等用例与事务边界 |
| 编排层 | 状态图执行、预算与截止时间、人工挂起 |
| Agent 层 | 分诊、诊断、评审、导师等单一职责单元 |
| 能力层 | 沙箱执行、静态分析、反例最小化、知识检索 |
| 数据层 | PostgreSQL（含向量扩展）、Redis、对象存储 |

设计上刻意不拆微服务：单体部署可在一台 16 核 32 GB 机器上支撑数百名学生，且模块间通过应用服务接口与领域事件通信，保留后续拆分可能。

### 3.2 双轴错因模型

**机制轴（M）** 描述技术根因，共 11 类：M01 类型与溢出、M02 数组与内存、M03 初始化与未定义行为、M04 边界与特判、M05 循环与终止、M06 复杂度、M07 取模与精度、M08 题意理解、M09 算法模型、M10 实现细节、M11 工程习惯。

**性质轴（P）** 描述教学严重度，共 6 档：

| 编码 | 名称 | 典型例子 | 判定方式 | 教学动作 |
|---|---|---|---|---|
| P0 | 表层/输入法 | 中文分号、全角括号、BOM | 规则（100%） | 一句话 + 自动修复 |
| P1 | 语法 | 缺分号、括号不配对 | 编译日志映射 | 报错翻译 + 知识卡 |
| P2 | 实现细节 | 越界、边界、初始化 | 沙箱 + 静态分析 | 反例 + 定位提示 |
| P3 | 算法模型 | 复杂度错、贪心不成立 | 对拍 + 复杂度探测 | 深度诊断 + 变式 |
| P4 | 题意理解 | 读错格式、漏条件 | 模型 | 重读题 + 标注 |
| P5 | 策略习惯 | 不打部分分、不测样例 | 画像 + 行为 | 教练介入 |

两轴正交：例如同为 M01 溢出，"会写但疏忽"属 P2，"不知道 int 有范围"属 P1，前者给反例即可，后者需补概念。

### 3.3 诊断流水线

```
提交 → 输入审核 → 分诊(Triage) → 判题取证 → 诊断 → 评审 → 教学
                      │
                      └─ 命中 P0/P1 → 快路径（秒回 + 自动修复）
```

分诊位于最前，是因为表层与语法错误在初学者提交中占比高，且可确定性判定；把它们挡在昂贵的取证流程之前，可同时降低时延与成本。

### 3.4 证据模型

系统定义六类证据：编译日志、运行轨迹、sanitizer 报告、反例、计时曲线、静态告警。每条证据具有类型、结构化载荷、内容摘要与可复现标记，作为一等实体持久化。诊断结论只引用证据编号，不直接引用源码文本。

### 3.5 证据闸门

结论对象的构造即校验：

```python
class CauseClaim(BaseModel):
    code: str
    confidence: float
    evidence_ids: list[int]

    @model_validator(mode="after")
    def _must_have_evidence(self):
        if not self.evidence_ids:
            raise ValueError("没有绑定证据，禁止 confirmed")
        return self
```

评审环节进一步校验证据编号是否真实存在、是否出现完整程序（防代做）、置信度是否与证据强度匹配。

### 3.6 提示阶梯

答疑按 L0 澄清、L1 方向、L2 定位、L3 反例、L4 修正逐级推进，L5 完整解析默认锁定。四条硬规则以代码实现：不得跳级、升级前需学生新输入、L4 需两次失败尝试、索要完整代码不升级且记录依赖信号。

### 3.7 反例最小化

给定失败输入，系统反复尝试删除其中一部分并重跑：

```
candidate = 删除 1/n 的块
若 validator 通过 且 学生输出 ≠ 参考输出 → 接受该候选，减小 n
否则 → 增大 n 继续
```

为避免删除后输入非法，采用两种策略：结构感知重建（保持元素数量与 `n`/`T` 一致）与 validator 二次校验。

## 4 关键技术实现

### 4.1 执行层抽象

生产环境使用 go-judge 作为沙箱，通过 REST 调用并做策略封装（资源限制、sanitizer 编译选项、输出截断）。开发环境因 WSL 内核对 `clone(CLONE_INTO_CGROUP)` 返回 EAGAIN，实现同接口的 Docker 执行器作为兜底。二者由配置切换，上层无感知——这一抽象本身也是工程必要性的体现。

### 4.2 表层错误检测

采用逐字符状态机区分代码区、字符串与注释，仅在代码区报错。该设计避免了对字符串内中文的误报——误报比漏报更损害信任。检测结果含行号、列号、码位与替换建议，并支持一键修复。

### 4.3 编译报错映射

将 GCC 诊断信息映射为学生语言，当前规则库 37 条，覆盖 `stray '\357'`（非 ASCII 字符）、缺少分号、括号不配对、未声明标识符、缺少 main、重定义、格式符不匹配等。

### 4.4 编排

采用 LangGraph 状态图承载流程，节点为纯函数（证据由外部注入），便于回放与测试；在其外围自研预算、截止时间与证据闸门，补足框架缺失的约束能力。

### 4.5 模型网关

统一出口负责超时、重试、降级与计费，密钥不落日志。模型调用失败时返回空值，由上层走降级路径，保证诊断链路不因模型不可用而中断。

## 5 实验与评估

### 5.1 实验环境

Windows 10 + WSL2 + Docker Desktop；PostgreSQL 16（pgvector 0.8.7）、Redis 7；模型为 DeepSeek-chat；题库 58 道（洛谷 26、GESP 32）。

### 5.2 分诊评测

样本 200 条（P0 160、P1 6、干净 34），结果：

| 指标 | 值 |
|---|---|
| P 档位准确率 | 100%（200/200） |
| 路由准确率 | 100%（200/200） |
| 全部样本耗时 | 8 ms |

### 5.3 反例最小化

| 错解 | 原始规模 | 最小反例 | 缩减 | 步数 | 耗时 |
|---|---|---|---|---|---|
| 求和 int 溢出 | 3000 元素 | 3 行 | 99.90% | 16 | 28.5 s |
| 求和少加一项 | 3000 | 1 行 | 99.97% | 12 | 21.5 s |
| 求和初值错 | 3000 | 1 行 | 99.97% | 12 | 21.7 s |
| 阶乘 int 溢出 | 600 组 | 1 行 | 99.83% | 13 | 23.1 s |
| 阶乘少乘一轮 | 600 组 | 1 行 | 99.83% | 10 | 17.9 s |

成功率 100%，平均输出 2.0 行，validator 合法率 100%，复现率 100%。

一个典型结果：20000 个 `1000000000` 被缩减为

```
3
1000000000 1000000000 1000000000
```

学生可用手算验证 `3×10⁹` 超出 32 位有符号整数范围。

### 5.4 端到端诊断

150 条构造样本（P0 60、P1 30、WA 60）：

| 指标 | 值 |
|---|---|
| verdict 准确率 | 100% |
| route 准确率 | 100% |
| P0 档位准确率 | 100%（60/60） |
| P1 档位准确率 | 100%（30/30） |
| WA 叙述关键词命中 | 81.7% |
| 时延 mean / p95 | 630 ms / 1694 ms |

### 5.5 消融实验

关闭模型（仅规则）后，在同一批 60 条 WA 上：

| 指标 | 规则版 | 规则 + 模型 |
|---|---|---|
| route 准确率 | 0% | 100% |
| 叙述关键词命中 | 0% | 81.7% |
| 平均时延 | 59 ms | 630 ms |
| 单条成本 | 0 | ≈ 1 次调用 |

结果表明：规则路径适合确定性场景，模型路径适合语义推断场景；二者边界清晰，组合使用优于任一单一路径。

### 5.6 案例分析

在规则完全无法判定的三个 WA 案例上，模型给出的定位均与真实缺陷一致：

| 真实缺陷 | 模型输出（摘要） |
|---|---|
| `a-b` 写成减法 | "输出 -10 而期望 50，确认题目要求的运算" |
| `i < n` 漏最后一项 | "循环只累加到 n-1，漏掉了 n 这一项" |
| 输出多 `sum=` 前缀 | "数值对但格式不对，核对是否多了前缀" |

三个案例的置信度分别为 0.55、0.55、0.40，均低于 0.75 阈值，系统据此将其标记为 `needs_human` 并转入人工队列，未直接呈现给学生。

### 5.7 局限与威胁效度

1. **构造集偏差**：150 条样本由注入缺陷生成，标签确定但分布与真实学生不同，P0/P1 的 100% 主要说明规则无误，不能外推为真实场景准确率。
2. **单一语言**：仅支持 C++17。
3. **单机规模**：未做多租户与并发压测。
4. **关键词指标**：WA 叙述命中率为自动代理指标，需人工评分替代。

## 6 总结与展望

本文把"错题诊断"从"让模型讲题"重构为"用证据约束模型"。核心结论有三点：其一，错因需要双轴建模，否则"笔误"与"算法错"会被混为一谈；其二，可验证性应当写进类型系统，而非寄望于提示词；其三，规则与模型不是替代关系，消融数据显示二者适用边界清晰。

后续工作包括：引入真实学生提交并做双评标注、扩展至多语言、支持校本部署与教师工作流。
