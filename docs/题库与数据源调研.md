# 题库与数据源调研（含选型决策）

| 项目 | 内容 |
|---|---|
| 调研时间 | 2026-10-29 |
| 方法 | 逐源 `web_fetch` 实测 + GitHub API 核验 + 许可条款原文核对 |
| 结论用途 | 决定 L1 教学题库 / L2 评测集 / L3 元数据 分别用什么 |
| 相关文档 | [需求分析](需求分析.md) · [系统架构设计](系统架构设计.md) |

> **一句话结论**：**技术上有得选，法律上没得选。** 中文 CSP-J/S 题面没有任何可自由再分发的合法来源；能"合法 + 带测试数据"的只有英文竞赛档案与公开数据集。所以 L1 题库只能**自命题 + 校内共建**，L2 评测集用公开数据集，商用落地再去谈授权。

---

## 1. 决策先行

| 层 | 用途 | 决策 | 理由 |
|---|---|---|---|
| **L1 教学题库** | 给学生看题、做题、诊断 | **自命题 40~60 道 + 校内教练共建 + OI Wiki 作知识库** | 唯一能"合法再分发"的中文内容源是 OI Wiki（且它是知识库不是题库）；题面必须自己写或学校提供 |
| **L2 评测集** | 只在内部跑指标，不再分发 | **DeepMind CodeContests（主力）+ APPS / TACO（补充）** | 带测试用例、许可明确（CC BY 4.0 / MIT / Apache-2.0）、可离线 |
| **L2' 反例源** | 找反例、做输入最小化 | **NERC/NEERC jury archive（tests+generators+solutions）** | 唯一"三件套齐全、免登录免申请"的档案；**但无 license 声明，仅内部研究用** |
| **L3 元数据** | 标签、难度、推荐 | **Codeforces API + kenkoooo(AtCoder)** | 免费、稳定；**只有元数据，没有题面** |
| **商用/落地** | 真实学校使用 | **洛谷开放平台签约** 或 **CCF 书面授权** 或 **校内题库** | 三条合法路径，见 §6 |

## 2. 判定标准（为什么很多"看起来能用"的源其实不能用）

一个数据源要进入系统，必须同时过四关：

| # | 关卡 | 说明 |
|---|---|---|
| G1 | **可再分发** | 要给学生看题面 = 向第三方分发。没有明确许可 = 默认保留所有权利 |
| G2 | **有测试数据** | 没有 testdata，就只能做静态分析，做不了对拍与反例最小化（系统的核心卖点） |
| G3 | **可程序化获取** | 有 API 或稳定下载；靠爬虫的方案在合规与稳定性上都不可靠 |
| G4 | **中文 / 适龄** | 青少年场景，英文题面是硬伤（需要翻译 = 衍生作品，另有版权问题） |

**四关全过的源：0 个。** 这就是为什么必须分层。

## 4. 五个必须知道的发现

### 发现 1：中文题面 = 零合法来源（最致命的约束）

CSP-J/S 真题的题面版权在 CCF，转载需书面授权；洛谷协议禁止再发行；第三方 GitHub 镜像（如各类 "noi 真题""CSP 题解"仓库）**授权链不明**，本次多数已打不开，法务风险最高。

**后果**：毕设 demo 里**不能出现照抄的 CSP 题面**。要么自命题，要么让学校提供（学校对自己出的题有版权）。

### 发现 2："禁抓"不等于 robots，而在于服务条款

洛谷 robots.txt 只禁了 `/record`、`/recordnew`、`/paste`，**题目页在 robots 层面是允许的**。很多同学据此认为"可以爬"——这是错的：**robots 只是爬虫礼仪，不授予版权许可**。系统设计文档里要写清这条，避免答辩被问倒。

### 发现 3：真正带 testdata 的只有三个

| 源 | testdata 完整度 | 可用性 |
|---|---|---|
| NERC/NEERC archive | tests + generators + jury solutions | ✅ 最完整，但**无 license** |
| CCF 申诉期数据 | tests（无 validator/标程） | ⚠️ 不可再分发，且缺 validator → 做不了安全最小化 |
| CodeContests | 成对 IO + 人类解答 | ✅ 可离线，许可清晰 |

其余全部**只有题面没有数据**。这意味着：**"对拍找反例"这个核心能力，只能建立在自建题包或这三个源上**——这正是架构文档里"题目包 A/B/C/D 分级"的现实依据。

### 发现 4：validator 比 testdata 更稀缺

输入最小化（ddmin）每一步都要验证"缩小后的输入仍然合法"。**没有 validator，缩小就可能产出非法输入，教学价值归零。**

- NERC 档案有 generator（可反推合法输入空间），但没有统一 validator；
- CCF 数据没有 validator；
- 自建题包可以自己写 testlib validator。

**结论**：**自建 40~60 道带 validator 的题，比收录 2000 道无数据的题更有价值。** 这是毕设工作量的正确投放方向：写题比爬题划算。

### 发现 5：数据集许可差异很大，但都能用

| 数据集 | 代码许可 | 数据许可 | 可否再分发 |
|---|---|---|---|
| CodeContests | Apache-2.0 | CC BY 4.0 | ✅ 署名即可 |
| APPS | MIT | MIT | ✅ |
| TACO | Apache-2.0 | Apache-2.0 | ✅ |

**注意**：这些数据集里的题目**本身来自 Codeforces 等平台**，数据集许可覆盖的是"数据集打包"，不必然覆盖原题版权。**内部评测（不再分发）是安全区**，对外发布结果时只报聚合指标、不贴题面。

## 5. 落地决策：三层怎么填

### L1 教学题库（要能给学生看）

| 来源 | 数量 | 谁写 | 说明 |
|---|---|---|---|
| **自命题** | 40~60 道 | 你 + 教练 | 覆盖 CSP-J/S 高频错因：溢出、边界、多清空、二分、DP 初始化、图论建模。**必须带 validator + std + brute + gen**（A/B 级包） |
| **校内题库** | 学校自有 | 教练 | 落地时的主力；系统提供"教师导入"入口，版权责任在校方（协议里写清） |
| **OI Wiki** | 全站 | 社区 | **只做知识库（RAG），不做题面**；署名 + 相同方式共享 + 给仓库 Star |
| **改写题** | 可选 | 你 | 基于经典模型**重写题面与数据**（不是翻译、不是照抄），可规避版权；需注明"改编自 XX 模型" |

**自命题的偷懒技巧**：不要从零想题。拿 OI Wiki 的一个知识点（如"前缀和"），设计一个**有边界陷阱**的小场景（如"n=0 时输出什么"），20 分钟一道。这类"坑点题"对诊断系统的价值远高于难题。

### L2 评测集（内部，不再分发）

```
CodeContests 抽样 300~500 条
  ├─ 每条：题面摘要 + 官方 tests + 正确解 + 错误解（天然带"错"）
  ├─ 人工标注：错因 M 编码（这是金标的核心工作量）
  └─ 用途：Top-1/Top-3 准确率、证据覆盖率、成本/时延
```

**为什么 CodeContests 特别合适**：它**同时提供正确解和错误解**——错误解就是天然的"学生提交"，省掉了自己造错题的成本。这是本次调研里最实用的一条发现。

### L3 元数据

- Codeforces：难度（rating 800~3500）→ 映射到 J/S/NOIP 档位；
- 知识点标签：CF tags（英文）→ 映射到 NOI 大纲节点（人工映射表，200 条左右）；
- 用途：推荐相似题、难度校准、班级分层。

## 6. 三条合法落地路径（真实学校要用时）

| 路径 | 成本 | 周期 | 适用 |
|---|---|---|---|
| **A. 校内题库共建** | 低（人力） | 立即 | 单校落地首选；学校出题、系统管数据 |
| **B. 洛谷开放平台签约** | 中（商务） | 1~2 月 | 需要海量中文题；注意协议是否允许缓存题面 |
| **C. CCF 书面授权** | 高（正式） | 3 月+ | 真题 + 官方数据；适合机构/出版社 |

> 简历/答辩表述建议："题库受版权约束，因此系统设计了**三层题库隔离 + 题目包规范**，把'能不能诊断'与'有没有授权'解耦——这是工程判断，不是技术妥协。"
