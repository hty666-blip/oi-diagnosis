## 0. 一页纸摘要

**做什么**：一个把"OJ 上的 WA"变成"有证据、可复现、能教学"的诊断报告的 Web 系统。学生提交代码，系统分诊 → 取证（编译/运行/对拍/最小化）→ 定位错因（机制 M × 性质 P）→ 分层提示，直到学生自己改对。

**三个维度都成立**：

| 维度 | 成立条件 |
|---|---|
| 毕业设计 | 有可论证的方法贡献（M×P 双轴 + 证据门控）、有实验（150 条金标）、有系统实现（可演示） |
| 可落地 | 单机 Docker Compose 能跑，一个班能用，成本 ≤ ¥0.3/次 |
| 简历 | 有"别人抄不走"的技术点：反例最小化、证据闸门、双轴分诊 |

**当前已有资产**（不必重做）：

| 资产 | 状态 |
|---|---|
| 8 份设计文档（需求/架构/选型/错因/题库×2/开源调研/技术验证） | ✅ 完成 |
| 洛谷题面采集器 + **26 道题 / 31 组样例 / 48 条标签** | ✅ 跑通 |
| 题包校验器 `check_package.py` + 示例题包 PTV-0001 | ✅ 跑通 |

## 1. 项目定义

### 1.1 一句话

> 用**确定性证据**约束 LLM，把"这题为什么错"变成一份可复现、可教学、可审计的诊断。

### 1.2 成功标准（三条，缺一不可）

| # | 标准 | 量化 |
|---|---|---|
| S1 | 诊断准 | 金标 150 条，Top-1 ≥ 70%，Top-3 ≥ 90% |
| S2 | 教得动 | 引导后 24h 独立改对率 ≥ 50%，平均提示层级 ≤ 2.0 |
| S3 | 跑得动 | 单机 Compose 一键起；快路径 P95 ≤ 1s，全路径 P95 ≤ 45s；单次 ≤ ¥0.3 |

### 1.3 明确不做（范围闸门）

- ❌ 不做完整 OJ（不重复造评测机，只做诊断层）
- ❌ 不做多语言（只 C++17）
- ❌ 不做公网多租户（单校部署，`tenant_id` 只做字段预留）
- ❌ 不做语音/手写/移动端原生
- ❌ 不做"一键出正确代码"（L5 默认关闭）

### 1.4 核心设计约束（不可违反）

1. 任何给学生看的代码必须编译 + 过样例（G2/G3 闸门）
2. 机制层结论必须绑定证据 ID，否则不许 `confirmed`
3. 确定性可判的事，绝不交给模型（Triage 规则优先）
4. 每次升级提示都要有学生的新输入（禁止跳级）

### W6 · M4 真实模型已接通（DeepSeek）

`LLM_API_KEY` 配置完成，`POST /api/v1/system/llm/ping` 返回 `ok`。模型只用在**规则判不了**的位置（`route=needs_human`），置信度封顶 0.6，结论一律标 `needs_human` 交教练复核。

| 案例 | 真实 bug | 模型给出的定位 | 机制码 | 时延 |
|---|---|---|---|---|
| wa_operator | `a-b` 写成减法 | "输出 -10 而期望 50，确认运算" | M08 | 1.8s |
| wa_range | `i < n` 漏最后一项 | **"循环只累加到 n-1，漏掉了 n"** | M04 | 1.2s |
| wa_format | `printf("sum=%d")` 多前缀 | "数值对但格式不对，核对输出格式" | M08 | 2.1s |

三个案例规则层完全判不了（无 P0/P1/P2 证据），模型的定位**全部与真实 bug 一致**。报告：`eval/reports/llm_hypothesis.json`。

> 安全设计：即使模型说对了，也不会直接展示给学生——`confidence≤0.6 < 阈值 0.75`，只能进教练队列。这是"宁可不说，也不说错"的落地。

| 学生端只有题目下拉，没有题面 | 只实现了 `/problems` 列表，没有详情接口 | 新增 `GET /problems/{pid}`；前端改成左右双栏（左题面+样例、右编辑器+结果），自带 Markdown 渲染（零新依赖） |
| 导师永远停在 L0、重复同一句 | `_can_advance` 里 `len(msg) < 4` 把"输出""计算"当成无效回答；且提示文案是常量 | 改为"非纯标点即有效"；新增 `不知道 → 给脚手架直接升 L1`、纯标点 → 换问法、回复接住学生原话、开场语按轮次轮换 |

**实测对话（修复后）**

```
L0: 你能用自己的话说说，这段代码打算怎么解决问题吗？
我: 不知道 → L1: 没关系，卡住很正常。我们换个方式：方向提示…
我: 输出   → L2: 好，那就先看输出。定位提示…
我: 计算   → L3: 行，我们先盯计算部分。反例提示…
我: 读入   → L3: 先按上面的提示试两次…（这是设计：L4 需两次尝试）
我: 我试了两次还是不对 → L4: 修正提示…
```

**测试**：89 条全过（新增 3 条覆盖短回答/放弃/标点）。

### W15 · 导师 v3：规则定边界，模型写措辞

**问题**：学生连说"不知道"，系统却一路升到 L4 然后复读同一句；回答生硬，像状态机不像老师。

**根因**：把"不会"当成了升级按钮（`is_confused → advance`），且提示文案是常量模板。

**重构**：

| 层 | 职责 |
|---|---|
| `decide()`（纯规则） | 判断升/停/讲/转人工，输出 `action + level + mode`，不生成长文本 |
| `compose()`（模型） | 把决定说成人话，受约束：不越级、不给完整程序、不编造数据 |

关键规则：

1. 同一层级里 `stuck_count` 累计"不会"次数：0 次 → 脚手架式前进；1 次 → **换一种讲法解释**（不升级）；2 次 → 转人工
2. L3 的"两次尝试"闸门**优先于**"我不会"，且闸门回复不交给模型改写（否则会被改写绕过）
3. 模型提示词新增：**禁止编造测试数据**，只能引用诊断给出的内容

**实测（同一串"不知道/真不会"）**：每轮回复都不同、逐层更具体，L3 闸门稳定拦住，第 5 轮自动降级为解释而非机械升级。

### 关于内存：这套系统其实不重，重的是 Docker 的虚拟机

实测（`docker stats`，空闲态）：

| 组件 | 内存 |
|---|---|
| PostgreSQL | 67 MB |
| Redis | 14 MB |
| go-judge（沙箱本体） | 30 MB |
| FastAPI（含 Python 运行时） | ~120 MB |
| **合计** | **≈ 230 MB** |
| 编译一个 C++ 文件的瞬时峰值 | +100~200 MB |

**结论：业务侧只要 300~500 MB。** 15.4 GB 的笔记本完全够。

真正的开销在别处：

| 项目 | 占用 |
|---|---|
| Docker Desktop 的 Linux 虚拟机（`vmmem`） | 3.8 GB（由 `.wslconfig` 的 `memory=` 决定） |
| DeepSeek Harness 自身 | 1.1 GB |
| 向日葵（AweSun） | 0.74 GB |
| Docker 后台进程 | 0.6 GB |

所以 `.wslconfig` 里那个 `memory=4GB` **不是需求，是上限**——我最初设 4GB 是为了让 WSL 能起来（默认会要一半物理内存）。现在已按实际情况降到 **3GB**（实测 VM 内只用 0.4 GB），Windows 侧空闲从 0.4 GB 回升到 1.2 GB。

> 如果还想更省：`memory=2.5GB` 也能跑（PG+Redis+judge+API 约 0.5GB），代价是同时跑前端 `vite dev` 时编译会慢一点。
