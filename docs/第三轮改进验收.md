# 第三轮：可恢复的后台判题与认证边界

日期：2026-10-29。上一轮提交 `ae6fe83` 已通过 GitHub CI，本机后端 214 项、前端 8 项测试通过。

## 目标与取舍

学生提交后应能关闭或刷新页面，稍后仍看到同一任务的真实状态；服务重启不能让提交永远停在运行中。继续使用模块化单体，先以 PostgreSQL 保存任务、领取锁与租约，不新增消息中间件；现有 Redis 可继续保留，但本轮不制造跨数据库写入一致性问题。

默认同步 API 保留兼容；前端显式申请异步执行，收到任务编号与查询地址后轮询真实状态。API 可在生命周期中运行判题工作器，也支持独立工作器进程。任务执行事实与模型解释分开，后台恢复不自动触发付费模型。

## 验收要求

1. 提交与持久任务在一个事务中创建，不出现已接受却无任务可执行的记录。重复请求复用同一任务。
2. 多工作器领取同一任务时只有一个有效拥有者；租约过期可恢复。旧工作器不能覆盖新工作器结果、证据或失败状态。
3. 超时、取消、执行器不可用时保存可理解的系统失败，有限重试；不会误判为学生 CE、RE 或通过。重试证据不混入之前的半次执行。
4. 页面刷新后恢复任务编号；202 仅表示接受。轮询有节制，终态停止，切题或退出后的旧响应不污染当前界面。
5. 教师审定和已验证的终态不能被后台重试静默覆盖；任务读取和重试继续执行对象归属校验。
6. 演示密码仅在明确开发演示环境提供；登录输入有长度约束，非法 token 或 claim 不导致 500 或权限扩大。生产配置缺少安全密钥时明确拒绝启动。
7. 用独立 PostgreSQL 测试任务领取、并发、租约恢复、旧拥有者拒写、认证边界；完成前端测试、构建与真实后台流程联调。

## 非目标与交接

本轮不引入课程、收费、多租户、全功能 OJ 或真实教学效果承诺。暂不进行外部付费模型评测，不提交真实环境配置、个人数据与运行缓存。

每个有效批次完成后更新 `docs/持续改进交接.md`，记录提交、验证、未解决限制和下一步。每日上海时间 00:18、06:00 的聊天续跑沿用该记录，避免重新扫描已完成项。
