# 初赛笔试模块新增需求

日期：2026-11-10。状态：需求及分期；第一批管理员候选导入与暂存已实现，学生笔试、知识库及成长路线仍待实现，并发指标未测。

候选数据进展：已完成 [离线核查](初赛题库候选数据验收.md) 和 [导入暂存验收](初赛题库导入暂存验收.md)。本地业务库已暂存 1120 条原始记录，全部待审核，未正式发布。去重、标签和计分问题保留为复核事项，尚未形成完整答疑知识库。

## 1. 本次调整

面向 12–16 岁青少年，以 CSP-J（入门级）、CSP-S（提高级）第一轮笔试的学习、错题诊断与答疑为新增主线；保留现有多语言编程练习、判题、教师复核及管理功能。J/S 按内容难度分级，不按年龄强制分组。

第一轮为笔试，第二轮为上机认证，参见 [CCF 官方通知](https://noi.ccf.org.cn/xw/2025-06-27/845923.shtml)。知识范围参考 [NOI 大纲（2025 年修订版）发布页](https://www.noi.cn/xw/2025-04-18/841584.shtml)，具体题型、分值、时限以所收录年份的试卷为准。

新模块建立“答题 → 规则判分 → 知识点诊断 → 针对性答疑 → 新题复习 → 学习记录”的闭环。原编程模块继续按正式测试、样例、无测试区分结果，不因缺少隐藏用例改成让模型判断 AC。

本需求补充 `docs/改进需求基线.md`：旧基线对原编程流程继续有效；其中“暂不做知识图谱”属于原阶段范围。本次新增轻量知识点关系与成长路线，以本稿约定的范围为准。

## 2. 现有基础与实际缺口

| 可复用的基础 | 需要新增或适配的部分 |
| --- | --- |
| 三角色登录、账号和班级管理、服务端权限 | 学生自助注册与班级邀请码；教师、管理员不得通过公开注册自选角色 |
| 编程题、题包导入、版本快照 | 笔试题、复合题组、试卷、标准答案与评分规则；不直接把编程题表改成通用笔试题表 |
| 提交历史、错题卡、教师训练与复核 | 笔试作答记录、错题本、简答复核及按知识点统计 |
| 独立模型请求、结构化交接和审查编排 | 笔试诊断与答疑 Agent 的输入、输出、工具和协作流程 |
| 学生档案、补练和历史会话 | 审核后的知识库、先修关系、跨会话学习记录与复习路线 |
| 模型配置、调用观察、后台任务和审计 | 笔试任务类型、知识来源与评分版本的审计 |

## 3. 三个角色的功能

| 角色 | 新增使用流程 |
| --- | --- |
| 学生 | 注册/登录 → 选择 J/S → 知识点学习、专项练习或整卷模拟 → 查看成绩与错题 → 诊断答疑 → 完成复习任务、查看学习路线 |
| 教师 | 选择本班题目或试卷并发布任务；查看完成情况、知识点错题分布和需要帮助的学生；复核简答与争议题；编写知识条目、题目解析及学习建议 |
| 管理员 | 管理账号、班级和权限；导入并审核题目、试卷、知识条目及来源；发布版本、处理答案纠错；沿用模型配置、任务观察、备份和审计 |

沿用学生本人、教师负责班级、管理员平台范围的权限。教师内容编辑与发布权限分别控制；学生知识记录和对话不能跨账号检索。

## 4. 笔试题库与判分

支持单选、多选、填空、判断、简答，也支持“共用题干/代码/图片 + 多个子题”的题组，用于程序阅读、完善程序等训练。简答可作为教学扩展，不把它描述为每年真卷都有的独立题型。

题目保存级别、知识点、选项、答案、解析、分值、评分规则和来源；试卷保存年份、组别、题号、题组顺序、时限与总分。作答绑定发布版本，修改题库不覆盖旧成绩。

| 类型 | 判分方式 |
| --- | --- |
| 单选、判断 | 服务端按审核后的答案精确比较，不调用 AI 判分 |
| 多选 | 按选项集合比较；漏选、错选和部分给分规则由试卷版本明确配置 |
| 填空 | 按每空配置的等价答案、数值或文本规则比较；不全局删除空白、单位或大小写 |
| 简答 | 教师配置评分要点；AI 提供草评、依据和建议分，教师确认后形成最终成绩 |
| 答案存在争议或缺失 | 标记待核对，不把无法判定记成学生答错；纠错后的重评分保留前后版本与记录 |

提供知识点专项、历年真卷、错题重练、限时模拟。模拟考试需要答题卡、自动保存、刷新恢复、服务端计时及幂等交卷；交卷前，学生接口不返回答案和解析，当前考试不开放 AI 答疑。AI 故障不影响客观题交卷和判分。

## 5. 真正构建题库与知识库

两类内容分别管理：题库保存练习和评分依据；知识库保存可以被引用的概念、规律、例子与解释。只存 PDF 路径或让模型凭记忆回答，不算建成知识库。

知识目录先覆盖计算机基础、信息编码与进制、计算机组成与操作系统基础、程序语言基础、数据结构、基础算法及相关数学；具体 J/S 范围按大纲核对，避免直接搬入大学整门课程。

每个知识条目至少有：稳定编号、名称、适用级别、先修知识点、正文、公式的适用条件、例题、易错点、来源定位、审核状态和版本。题目关联知识点，必要时为干扰选项配置可能的误区；一次选错只能支持诊断假设，不能证明固定的认知缺陷。

建设流程：

1. 收集可使用的真实试卷、答案及教学资料，登记来源、年份、页码和使用范围；区分官方答案、教师校订答案、回忆版与自编题。
2. 将题干、选项、代码、图片、公式和答案结构化导入，预览后人工逐项校对；OCR/模型抽取仅生成草稿。
3. 按知识目录编写并审核知识条目，建立题目到知识条目、条目到先修知识的关联。
4. 审核后发布可检索版本；无确定答案的题不进入自动评分。引用材料的公开可读状态不等于允许在公开仓库全文再分发，按来源许可保存链接或授权内容。
5. 用检索样例验证能找到正确条目，并让讲解携带可打开的条目编号和版本。先实现 MySQL 分类与关键词检索；实际召回不足时再增加向量检索。

初期先验收一套有明确来源与校订答案的 J 卷、一套 S 卷，以及至少 20 个完整知识条目；这是拟定交付目标，不是当前数据规模。真题数量不足时明确展示自编练习，不将生成题冒充真题。

## 6. 两个 Agent 的实际协作

客观分数由规则服务给出，两个 Agent 在此基础上分工，并使用独立请求、结构化交接和可查询记录。

| Agent | 输入与工具 | 输出与责任 |
| --- | --- | --- |
| 诊断 Agent | 固定题目版本、学生作答、规则评分、审核后的答案与知识条目、本人相关历史；检索知识与学习记录 | 区分作答事实和错因假设，给出知识缺口、引用来源、待确认问题和答疑建议；材料不足时保留未知 |
| 答疑 Agent | 接收诊断交接，结合学生当前追问与引用条目；可重新检索并请求诊断修订 | 针对具体误区解释、举例和讲解程序；学生说不会时展开步骤；最后提出一道已审核的新题或复习任务 |

交接记录包括作答编号、题目/知识版本、评分事实、诊断假设、引用编号与下一步建议。两个 Agent 不能只是同一回复里使用两个角色名称。可以复用现有独立审查能力检查引用、越界结论和意见驱动修订，但不要求每次都调用更多模型。

学生再次学习二叉树时，系统检索其上次错误、已讲内容和复习结果后交给 Agent；“记住学生”由授权数据库记录实现，不依赖模型永久记忆。切换账号后不得带入上一人的内容。模型不可用时显示规则评分、审核解析及可重试状态，不伪造 AI 已完成诊断。

## 7. 学习路线与示例

路线由先修关系、真实作答和教师建议生成，例如：节点与边 → 树 → 二叉树 → 层数/高度 → 节点数性质 → 程序应用。显示已练习、待巩固、待复习和复习记录；未被观测的知识点保持未知。一次答对、看过解析或发送多条消息，都不等于掌握。

例题必须说明条件：“根为第 1 层、共 h 层的二叉树，最多有多少个节点？”答案为 `2^h - 1`。只问“二叉树最多多少个节点”而不限制规模或高度，没有固定有限答案；高度按边数定义时公式也会变化。

学生混淆“第 h 层节点数”与“整棵树节点数”时，诊断 Agent 引用知识条目提出这一假设；答疑 Agent 用 1、2、4 个节点的层级例子解释，再安排不同条件的新题。保存初答、是否看过提示、讲解、再练与间隔复习结果；不把同题记住答案算作独立复习通过。

## 8. 技术选型与并发目标

沿用 React + TypeScript / Vite、FastAPI / Python、SQLAlchemy / Alembic、MySQL 8.4 和 LangGraph。新增笔试领域模型和服务，复用身份、班级、模型网关及后台任务。暂不为这一模块更换后端语言、拆微服务或引入独立图数据库。

模型先沿用已接入的 DeepSeek，Kimi 作为可选供应商，经适配和同题评测后再启用。两个 Agent 可以使用同一模型；供应商数量不等于 Agent 数量。DeepSeek 支持 [JSON 输出](https://api-docs.deepseek.com/guides/json_mode/)，但服务端仍需检查字段、引用和权限，不能把 JSON 格式正确当作知识正确。

不能仅凭技术栈承诺最多在线人数。首期建议用“100 个在线会话、30 人同时练习、最多 5 个 AI 请求同时处理”作为待验证场景，超出 AI 并发的请求排队或明确返回繁忙。这些是测试目标，不是已达到的容量；实际限制取决于部署硬件、请求频率、模型额度和响应时间。

压测分别记录普通答题接口的吞吐、p95 延迟和错误率，以及 AI 排队时间、超时和恢复结果。常规自动化使用模拟模型及独立 MySQL；真实模型小样另行记录调用量。前端继续按现有桌面端设计规范实现。

## 9. 实施顺序与验收

| 批次 | 交付范围 | 完成依据 |
| --- | --- | --- |
| 1：先能可靠做题 | 学生注册、笔试题/题组/试卷、来源校对发布、客观评分、作答记录与错题本；优先跑通 J，兼容 S 数据结构 | 真实内容可导入并作答；错误答案能被准确判错；断线恢复、重复交卷、版本固定及越权检查通过；模型关闭仍能完成闭环 |
| 2：真知识库与协作 | 审核条目、知识关联与检索、两个 Agent 交接答疑、简答草评及教师复核 | 可追溯到知识来源；两次独立角色调用和交接可见；“不会”的追问得到具体解释；未知、争议和模型断连处理可复现 |
| 3：学习与带班闭环 | 成长路线、间隔复习、专项/整卷任务、限时模拟、班级学情和教师建议 | 新题复习结果更新路线；教师仅查看本班；模拟交卷前无答案泄漏，交卷后成绩与规则一致 |
| 4：数据与展示验收 | 扩充 J/S 真题与条目、标注题集评测、并发压测及演示脚本 | 逐项公布实际数据规模、错误/复核情况、模型指标和压测条件，不把计划数字写成实测结论 |

首个演示闭环选“二叉树知识专项”：教师发布 → 学生作答 → 规则判错 → 诊断 Agent 定位可能混淆 → 答疑 Agent 展开解释 → 新题复习 → 学习路线留痕 → 教师查看。原编程练习入口和历史记录继续保留。
