# 教练端使用与演示

## 当前流程

题库由管理员校验、导入并上架。保存训练时固定题目版本，更新题库不替换已发布任务；旧草稿遇到版本更新时需核对后新建训练。学生题面有版本标记，继续历史修改和另开最新版练习是两个明确操作。详见 `管理员端题库与版本验收.md`。

教练登录后进入“训练工作台”，查看账号已有的班级名单，布置题目、必做/选做、目标、说明和截止时间。保存草稿并核对范围，再发布。学生在“我的训练”接收，进入题目后继续使用多语言编辑、可信判题和直接代码讲解。

完成矩阵按本训练最新提交展示；打开学情可查看单题人数、修改结果和带证据的共性问题。AI 讲评是可编辑草稿，教师预览后单独发布，学生只能看到已发布版本。模型不可用时显示事实提纲。新提交或复核使旧依据过时，核对后保存再发布。

在学生行点击“指导与补练”，可发送私有反馈并选择依据提交。学生可明确标记查看；系统分别记录查看、新提交与正式通过。教练可以为该学生预填补练草稿，再换题、设置范围并发布。指定补练只发给选定的原训练成员，不自动发全班。

“学生档案”按学生汇总训练、最近指导与补练；学生有“我的档案”，可继续练习或打开训练。双方都能导出授权范围内的 Markdown 档案，导出内容包含汇总时间与最近反馈，不自动附带提交源码。

## 建议演示顺序

1. 管理员在“平台管理”创建班级、分配负责教练并为学生分班；新账号首次登录先改密。也可使用已有独立演示账号。教练布置自建题 `PTV-0001`，作为必做题发布。
2. 学生提交存在累计更新错误的自编代码，展示实际失败用例、源码和 AI 直接讲解。
3. 教练打开完成矩阵，查看证据和共性问题；生成、编辑、预览并发布讲评。使用真实模型需本地配置开启，演示时说明实际来源。
4. 教练向该学生发送个别反馈，绑定实际错误提交；学生标记查看、修改并重新提交，展示正式题包通过。
5. 教练安排仅该学生接收的补练，核对原训练关联、目标人和题目后发布；学生完成补练的独立提交。
6. 打开师生档案，展示原训练、补练及反馈后的结果，下载档案报告。题包测试通过只说明当前测试范围，不声称学生独立完成或完全掌握。

## 边界与后续

班级使用稳定编号和明确教练负责关系，支持多班教练、改名、归档、转班及存量训练转交，详见 `管理员端账号与班级验收.md`。当前不含正式机构多租户管理。档案最多汇总最近 100 份可见训练，单个训练反馈显示最近 50 条。演示使用自建或合法公开题目和合成账号，不把构造样例称为真实教学效果数据。

三批验收分别见 `教练端训练任务验收.md`、`教练端学情与讲评验收.md`、`学生档案与补练验收.md`。后续应从真实课堂试用发现的问题推进，优先可解释性、响应速度、数据量边界和教师反馈，不继续堆砌未经验证的掌握度分数。
