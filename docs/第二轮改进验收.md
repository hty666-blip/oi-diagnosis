# 第二轮改进：可继续、可复核的修复流程

日期：2026-10-29。前提：首轮判题范围、学生归属和修改核验回归已通过，首个 GitHub CI 为成功。

## 用户与目标

学生需要从实际失败证据继续修改，保留版本之间的关系；教师需要真正处理证据不足的诊断，而不仅是看到一个待复核数字。本轮沿用现有技术与布局，继续优先保证核心流程可靠。

## 范围与规则

- 提交可带上次提交编号，服务端校验同账号同题并保存版本关系；缓存不得把不同修复链混成一条，失败后可重试。
- 一次修复的前后代码、结果和证据可追溯；终态和系统错误在界面有明确恢复动作。
- 教师可查看本班提交的证据，确认、修订或退回诊断；每次操作写入独立审计记录，保存操作者、时间、版本及变更前后内容。
- 人工复核不得改写机器判题结果；证据引用必须属于本次提交，过期版本不能覆盖新审定，学生无权审定。
- 自动重新诊断不得静默覆盖人工审定；学生能区分机器建议、人工审定与仍待核对的内容。
- 辅导直接使用真实失败输入与输出；未证实的根因明确保留为假设，未缩减的用例不称“最小反例”。模型不可用时仍返回可操作的证据提示。

## 非目标

暂不引入队列服务、多租户、课程、付费或学习成绩预测；不因界面改进宣称诊断准确率或真实教学效果，不执行外部付费模型评测。

## 验收

1. 真实 PostgreSQL 接口测试覆盖提交父子关系、跨账号/异题拒绝、缓存范围和复核权限。
2. 教师审定可回放，重复或过期操作不会覆盖，自动诊断保留人工结果。
3. 真实浏览器跑通学生错解、证据、提示、修改重提与核验；教师查看并处理复核记录。
4. 后端静态检查、相关回归、前端构建通过；更新文档中的已实现项和限制，公开仓库继续排除真实密钥及运行数据。

## 本轮交付记录

- 新增父提交关联及祖先链查询；缓存按学生、题目、代码、父版本和测试版本区分。同一请求并发到达时只编译一次；取消执行后允许重试。
- 新增教师复核接口与独立审计表，保存变更前后、证据编号、操作者和版本。数据库拒绝修改或删除已保存的审计记录；自动重诊断和人工审定都递增版本。
- 模型建议保留“待核对”边界，教师审定不改变机器判定。模型开关关闭时健康信息明确显示禁用，模型探测接口也拒绝外部调用。
- WA 直接复述真实输入、实际与预期输出；未定位时不编造行号，未缩减用例不称最小反例。截断输出保留原判题匹配标记，避免相同前缀掩盖差异。
- 后端 214 项测试通过，包括独立 PostgreSQL、真实多连接并发复核与重复提交、真实 Docker C++ 错解修复；Ruff 通过。前端 8 项契约与呈现测试及构建通过。
- 真实浏览器隔离联调地址为 `http://127.0.0.1:5174`，对应禁用模型的 `18000` 后端。已验证求和错解提交 #68 为 WA（2/3），溢出测试输出 `1410065408`、预期 `10000000000`；改用 `long long` 后 #69 为题包 AC（3/3），显示 #68 → #69 关系且答疑核验解决。上述编号仅为本机演示记录。
- 教师在真实界面查看 #68 的失败证据并修订诊断，保存审定版本 3；待复核数由 13 变为 12，审计展示操作者、时间及引用的证据，原提交的 WA 判定未被修改。

仍有限制：判题采用同步请求，尚无跨进程崩溃恢复的持久任务；审计不可变规则暂未与用户数据删除策略整合；浏览器验证不能替代真实课堂效果评估。原始配置服务与隔离联调服务分开，使用自定义前端代理时可设置 `OI_API_TARGET`。

教师审定后，学生重新登录可在提交记录看到教师已复核，并能打开修订说明、证据编号及审计版本。旧版样例通过摘要在详情、历史和错题卡中统一显示验证不足，原始诊断与审计数据保持不变。
