# 第四轮：任务取消、旧记录兼容与可观测状态

日期：2026-10-30。第三轮 `898bd0b` 的后端 280 项、前端 18 项测试及 GitHub CI 已通过。

## 问题与范围

后台任务已经可恢复，但学生提交后无法主动取消错误任务，修改意图后仍会占用判题资源。另一个兼容缺口是无持久任务的旧同步运行记录：新异步请求可能命中它并持续等待，无法得到自己的可恢复任务。教师和管理员也缺少真实后台积压的视图。

本轮仍沿用 PostgreSQL 工作器和现有布局，不增加中间件。取消、过期和失败是不同事实；不可把用户取消记作 CE、RE 或测试通过。

## 验收规则

1. 学生可取消自己的排队或运行中持久任务，管理员可处理全部；同班教师的读取权限不扩大为取消学生任务的权限。取消重复调用幂等，已成功结果不能被取消覆盖。
2. 取消在同一数据库事务中使任务终态化并撤销租约；旧执行者的下一次写回和心跳不能恢复或覆盖该任务。取消与完成并发时只能得到一种有效终态。
3. 界面明确“已取消”，停止轮询并保留代码、父链和历史；不能显示通过，也不自动触发诊断或答疑核验。重新提交创建新的可追踪任务。
4. 显式后台提交不复用无任务的旧同步活动记录；旧记录保持原样，不擅自把仍可能运行的请求标记失败。相同后台请求仍复用唯一持久任务，已完成缓存仍可复用。
5. 教师/管理员可查看授权范围内真实队列数量、等待时长与失败信息，学生不能读取其他人的队列情况。没有工作器心跳证据时不宣称工作器在线或离线。
6. 用独立 PostgreSQL 验证权限、取消/完成竞争、旧写入拒绝、旧同步缓存兼容；前端覆盖取消终态与恢复，并完成真实取消后重新提交流程。
7. 请求中的空字符、非法 Unicode 在保存前返回 422，不能写入提交、答疑或复核审计；校验错误仅返回字段、类型与原因，不回显密码、请求值或验证上下文。

## 实施与验证

- 新增 `cancelled` 持久终态和迁移 `f0d26c31a8b4`；有取消记录时拒绝降级到不支持该终态的旧数据库结构。
- 学生本人和管理员可取消排队/执行任务，重复取消幂等；取消与完成使用同一行锁，旧执行者的写回与心跳均被拒绝，已完成或教师审定结果保持原样。
- 新异步请求跳过没有持久任务的旧同步活动缓存；后台重复任务和已完成结果仍可复用。
- 教师摘要按账号/班级范围汇总五类状态、可执行后的最长等待和互斥租约计数；最近失败最多五条，仅展示安全文案。
- 统一处理请求校验错误，并校验登录用户名、题库搜索、提交代码、答疑和复核文本；合法中文、emoji、BOM与空白按既有规则保留。
- Docker 构建上下文排除真实环境配置和私钥；开发脚本在迁移前拒绝非开发环境。已验证真实 `.env` 无法被 Docker `COPY` 带入镜像，生产配置会在迁移前停止启动。
