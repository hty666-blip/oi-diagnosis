# 第七轮：学生退出码与执行器故障区分

日期：2026-10-31。基线 `cfb6157`，上一轮后端 373 项及 CI 已通过。

## 已复现问题

真实 Docker 运行正常编译的 C++ 程序，自行返回 124 会被记作超时，返回 125、126、127 会抛出执行服务异常。学生的非零退出会因此触发无意义重试，或得到错误的运行证据。原因是学生退出码直接与 GNU timeout、Docker CLI 的保留退出码共用同一通道。

## 修复与边界

- 容器内先检查产物存在且可执行，再在 timeout 内包装学生程序；包装只返回成功或失败，通过本次独立状态文件保存原始学生退出码。
- 读取状态文件时限制大小，拒绝链接、无效值、缺失及与包装状态矛盾的结果；这些情况不能被判为通过。结束后清理本次状态文件。
- 学生自行返回 124–127、137、139、255 均为 RE，保留原始退出码；外层真实超时仍为 TLE，Docker 启动失败仍为系统故障。
- 参数逐项传入，不拼接到执行脚本；空格、引号和 `$()` 按字面值传给程序。
- 流水线升级为 `v6`，避免复用旧版错误判定。未变更数据库结构、对象授权或前端布局。
