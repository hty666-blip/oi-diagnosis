# 学生档案与补练验收

日期：2026-11-02；基线 `cdbc29c`。本批完成教练端第三批：学生训练档案、个别指导、定向补练、后续结果与报告导出。

## 功能与依据

- 教练“学生档案”和学生“我的档案”汇总最近最多 100 份当前有访问权限的已发布训练，显示题目、最新执行结果、必做完成情况、补练来源和最近个别反馈。自由练习仍从原提交记录查看；更多历史明确提示不在本次汇总内。
- 教练可在完成矩阵点击“指导与补练”，向单个名单学生发送反馈，可引用该学生本训练的一次实际提交，也可作训练整体指导。反馈追加保存，使用请求编号避免网络重试重复发送；变化内容复用旧编号会被拒绝。
- 学生明确点击“标为已查看”才记录查看时间，重复标记幂等，教师及其他学生不能代标。查看不改变判题或掌握度。
- 后续状态按反馈保存时的提交编号边界和本训练最新提交派生。旧任务晚到的通过结果不算重新提交；样例通过、执行故障和其他训练不能算反馈后正式通过。整体指导还要求新增必做提交与整体完成，避免选做重试冒充修复。
- 定向补练关联原已发布训练，必须指定原训练名单内且当前仍在本班的学生，可重新选题、设置截止时间并预览发布。训练和补练各自计数、代码草稿与提交隔离；原题通过不能替代补练提交。
- 学生仅能看到自己的私有反馈、档案和分配训练；教师仅本班学生及自己布置的训练，管理员按既有授权范围查看。学生列表和详情不暴露定向接收人编号列表，转班会失去原班访问权。
- 档案可下载为 Markdown，包含时间范围、训练状态、最近反馈与后续情况，不自动附带提交源码。导出接口再次检查归属，响应禁止缓存；正文迟到且账号已切换时前端不创建下载。

## 并发与兼容

反馈与训练提交创建共享短事务训练锁，固定反馈发生时的提交边界；判题执行期间不持锁。并发重复反馈只保存一条。反馈不覆盖教师诊断审定，补练也不修改原训练数据。
