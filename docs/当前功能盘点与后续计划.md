# 当前功能盘点与后续计划

基线：2026-11-18，提交 `5acc4d0`，[PR #1](https://github.com/hty666-blip/oi-diagnosis/pull/1) 待合并。[CI](https://github.com/hty666-blip/oi-diagnosis/actions/runs/44234733440) 后端 779 项（含真实四语言判题）、前端 83 项通过。本机 MySQL 8.4.11、迁移 `v678c29e3a5f`。

**项目主线：以 CSP-J／CSP-S 初赛训练为毕设演示重点，保留原编程判题线。** 优先让初赛在一套受控环境里有题可做、有讲义可查、能演示 Agent 交接，并让学习结果回到教练的班级学情。

## 已实现功能

| 角色 | 初赛笔试 | 编程训练与平台功能 |
| --- | --- | --- |
| 学生 | 按级别、题型、试卷或知识点找题；四类客观题自动判分；查看记录、错题订正及学习路线；参加班级专项和客观题限时模拟；专项简答提交后查看教师反馈；就错题追问并查看 Agent 交接 | 四语言编辑、提交和证据查看；断线后恢复提交、代码草稿与答疑；读取源码讲解、重新提交核验；查看训练、个别反馈、补练及个人档案 |
| 教练 | 从已上架题目选题、设截止时间、向本班发布专项；看逐题学情；按固定版本逐项复核简答，可选择用 AI 草评 | 管理编程训练、进度矩阵和共性错因；诊断确认、修订或退回；编辑并发布讲评；发个别反馈、定向补练、导出授权学生档案 |
| 管理员 | 预览及暂存 ZIP，核对来源和答案，管理审核版本及上下架；编辑、审核和发布知识条目；查询 J/S 覆盖、答案冲突和待审题 | 创建及批量导入账号、建班、分配教练、转班、归档；管理编程题包版本；查看判题工作器、任务与 AI 配置；做加密备份、空库恢复验证和操作审计 |

学生、教练和管理员均可登录、修改密码，现有开户由管理员完成，尚无学生自行注册入口。各角色按本人、负责班级或平台范围访问。

## 多 Agent 具体做什么

| 场景 | 协作方式与判定边界 |
| --- | --- |
| 初赛客观题答疑 | 规则服务先出分；诊断 Agent 使用固定版题面、学生作答、审核讲义及相关历史形成错因假设；答疑 Agent 接收交接，按当前追问解释。两位角色用独立模型请求，交接和引用可回看。 |
| 初赛简答复核 | 草评 Agent 按要点建议给分并引用学生原文，系统先查分值和引用，复核 Agent 再检查建议。教练可采纳、修改或直接手评，确认后才发布成绩。 |
| 编程错题 | 沙箱输出编译和测试证据；复杂失败由证据分析、诊断、独立审查角色交接，必要时退回修订，再交给答疑 Agent。正式通过取决于题包测试，样例通过单列。 |

模型不可用时，客观题照常判分、简答照常手评，初赛答疑回退到审核解析。技术基线为 React／TypeScript、FastAPI、MySQL 8.4 和 Docker 判题执行器，模型通过兼容接口接入。已经用 DeepSeek 和原创样例验收；Kimi 尚无等量实测结论。

## 当前缺口

- **首要是上架内容。** 本机只读核对：1120 道采集候选仍待审，已上架初赛题和知识条目均为 0。仓库可复现的原创素材有 16 道客观题、1 道简答、8 篇讲义源稿；素材随仓库提供，上架要走审核发布。采集包 28 套中有 5 处答案冲突、4 套分值合计异常，时限尚未逐卷核对。
- **评分有范围。** 多选目前按完整选项集合全对得分；填空支持审核后的文本等价答案和首尾空白规则。按试卷给部分分、逐空规则、争议裁定后的批量重评分尚未做。简答只在班级专项；整卷限时模拟仅开放完整上架且元数据齐备的客观题卷。
- **学习路线有证据，复习任务尚未连起来。** 现有界面从近期作答生成知识点状态并推荐同级未做题；尚无间隔复习提醒、教师配置复习目标或按整卷错题发起后续专项。
- **已有并发样本，尚未定生产容量。** [本机实测](初赛并发实测.md)覆盖 100 人同时读题、30 人同时交卷和混合流量；混合场景交卷 p95 为 1.915 秒，正式三轮共 690 次请求通过。真实模型高并发、整卷截止集中提交、长时间负载和生产部署还要单测。

## 实施计划

| 顺序 | 任务和交付物 | 验收标准 |
| --- | --- | --- |
| P0 · 演示基线，1–2 天 | 在独立 MySQL 用合成账号准备 J/S 原创卷、简答和配套讲义；建立一键准备与检查入口，汇总桌面演示脚本。更新 README 的当前启动、迁移和功能口径。 | 从新库起步走通：管理员审核 → 教练布置 → 学生答错 → 双 Agent 交接 → 新题复习 → 教练看学情。附演示两分支：模拟刷新交卷、简答手评；模型关闭也能完成评分。 |
| P1 · 第一批可信内容，开发与人工校对分开排 | 先挑各 1 套有可核对原卷和答案的 J/S 卷，保留来源、勘误及使用范围；逐题核对题组、图片、选项、答案、分值和时限。同步把完整审核讲义扩到至少 20 篇，优先进制、组成原理、操作系统、树、栈队列与基础算法。 | 每道发布题可追溯到审核记录，冲突、撤题或规则未知不参加正式评分；若真卷不齐或未确认可用，展示明确标注的自编卷。随机检查讲义检索、题目链接及 Agent 的引用版本。 |
| P2 · 真实使用流程 | 先补仅限学生的班级邀请码注册，与管理员开户并存；再补「模拟错题 → 知识点复习 → 新题验证 → 教练查看」。优先复用现有答卷和班级任务，再按已核准真卷补多选部分分或逐空规则。 | 无效、过期邀请码和异常注册不能入班；所有记录限本人或负责教练。模拟成绩保留原分，复习结果单独记录，未练过和做过一次要能区分。 |
| P3 · 论文实验与课堂试用 | 用抽样标注的原创或获准材料，对比单 Agent、双 Agent 和审核解析；复测集中交卷与模型关闭场景。整理三端演示、交接证据、技术架构和实验结果。 | 报告样本量、人工标注方法、错因命中率、引用准确率、延迟与用量。并发记录写明机器、流量、失败率和 p95；试点前核对模型输入范围、权限隔离及备份恢复。 |

**P0 入口已接入。** [一键演示与验收步骤](初赛演示流程.md)使用独立 MySQL 和原创材料。上文的真实候选题上架数仍按业务库口径记录，临时演示不计入。下一步先按 P1 准备 J/S 各一套卷的来源和评分规则核对清单，人工审过一批再发布一批。桌面优先，现阶段不扩手机端或公开多租户部署。

本轮按用户要求优先做功能。P2 已接上[答卷错题复练](初赛试卷练习验收.md#交卷后错题复练)，支持复练记录和返回原卷。围绕同知识点的分组复习、推荐新题与教练跟进待接；暂缓继续整理采集题。
