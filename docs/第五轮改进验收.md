# 第五轮：输入边界与跨标签账号一致性

日期：2026-10-30。基线为第四轮 `4c906b1`。

## 已复现问题

Python 整数不受位数限制，提交和答疑接口直接将路径或请求体编号绑定到 PostgreSQL `BigInt`。编号 `9223372036854775808` 会导致数据库异常及 HTTP 500，涉及提交详情、证据、会话、新建答疑、修改核验和教师复核。题目详情路径中的 `%00` 也会在查询时触发数据库异常。

另一个真实界面问题发生在多标签页：标签 A 登录 `student01`，标签 B 切到 `student02` 后，A 仍显示前一个账号，却在刷新时读出后一个账号的记录。原因是页面账号状态未更新，而请求每次直接读取共享存储中的新 token；这还可能让旧草稿以新账号提交。

## 验收规则

1. 路径对象编号为 `1..2**63-1`；正常路径字符串仍可解析，不要求客户端改变 URL。零、负数和越界编号在访问业务数据前返回 422。
2. 请求体中的提交、父版本、学生和证据编号采用相同范围，必须是 JSON 整数；不把布尔值、小数或字符串隐式变成其他记录编号。原有可选 `null` 仍可使用。
3. 合法但不存在的编号仍返回原有 404，真实对象的所有权、同班教师范围及父版本规则继续生效。
4. 题目详情路径题号为 1–32 个合法可保存字符；空字符或超长文本返回 422，合法中文题号保持可查询。
5. 独立 PostgreSQL 接口回归覆盖各路由族和输入族；拒绝请求不产生提交、任务、答疑轮次或复核审计。
6. 每个标签的请求绑定该标签已确认的登录快照；共享账号变化后，旧标签不得用新 token 发出受保护请求，返回中的旧请求也不能更新当前界面。
7. 跨标签切换使旧账号界面卸载并停止查询；原账号草稿保留，另一标签的新账号存储不被旧请求、401 或退出动作清除。当前页重新使用需显式登录，公共登录与演示入口仍可用；完整刷新按既有自动登录规则完整初始化共享当前账号，不复用旧界面状态。
8. 使用两个真实浏览器标签复测账号切换，并为发请求前/返回后的会话变化补必要契约回归。

本轮不改数据库结构、不放宽授权、不删除历史数据，也不调整已采用乐观比较的复核版本号。外部模型继续关闭。

## 实施与验证

共享对象编号类型已覆盖全部提交、答疑路径与正文编号；路径保留正常整数解析，正文拒绝隐式转换。题号详情使用与存储一致的文本校验。

前端为每个页面保存已确认的会话快照，在受保护请求发出前、响应返回后和正文读取后核对身份；共享存储变化会使旧页面失效。公共请求不携带账号凭证，迟到的 401、退出及旧响应不能破坏新登录。
