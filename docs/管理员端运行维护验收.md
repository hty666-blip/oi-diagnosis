# 管理员端运行维护与备份

## 功能与演示路径

管理员登录 → 平台管理 → 运行维护。学生和教练不能访问管理配置、备份和任务处理接口；教练原有诊断复核与连通检查保留。

1. **判题运维**：查看队列、按状态和题号/用户名筛选任务；核对提交、学生、固定题目版本和尝试次数后重试或取消。状态已变化返回冲突，已完成和经教师审定的结果受到保护，处理与审计同事务保存。工作器每五秒写独立心跳，超过阈值不计在线；任务租约和空队列不能证明进程在线。
2. **执行器检查**：选择 C++17、C11、Java17 或 Python3，实际编译运行固定 OK 程序。只证明所选语言本次执行成功，记录时间、执行方式和结果，不替代整题评测。
3. **AI 服务**：显示当前调用开关、配置来源、模型与地址。填写候选配置，检查只发送固定短文本；检查通过后十分钟内可单独启用。检查与启用绑定管理员、配置版本和有效期，失败保留原配置。更换地址必须重新填写密钥；密钥加密保存、不回显、不进入审计。停止调用后后续业务使用规则降级，进行中的调用可能继续完成。
4. **备份**：创建后任务异步执行，可离开再返回查看。生成后下载 `.oibak` 加密文件，展开清单查看 SHA-256、结构版本及逐表记录数。下载成功与恢复验证分别呈现。
5. **恢复验证**：仅在专用空库执行迁移、导入、逐表内容比对及题目版本摘要校验，随后清理。成功后显示验证时间；失败显示原因及可用的重试操作。维护任务有续租、失效执行者隔离及最多三次尝试，进程中断后可接管过期任务。

## 部署配置

先停 API，执行 `alembic upgrade head` 升至 `m7e93da8152b`，再启动。API 默认同时运行判题和维护工作器；`MAINTENANCE_WORKER_ENABLED=false` 可关闭本进程的维护执行。关闭后仍能接受任务，须另行启动启用维护工作器的 API 进程。

`LLM_ENABLED=false` 是部署级开关，页面不能绕过。数据库无管理配置时沿用环境配置；启用管理配置后，后续答疑、诊断和讲评逐请求读取同一数据库版本。管理密钥的加密派生自 `JWT_SECRET`，更换该值后须重新填写模型密钥并检查；不要把真实配置提交 Git。

默认备份目录为 `data/private/backups/`，密钥单独保存在 `data/private/backup.key`。可用 `BACKUP_DIRECTORY` 指定目录，密钥位于该目录的父目录。备份和密钥须分别存放于受控的持久存储，维护操作系统访问权限；没有原密钥无法解密。仓库忽略默认私有目录，但自定义目录需自行排除。Docker 部署需挂载持久目录，数据库逻辑备份不包含部署程序和未纳入数据库的旧题包文件。

`BACKUP_VERIFY_DATABASE_URL` 指向**同一 MySQL 实例**的专用空库，驱动为 `mysql+asyncmy`，库名必须包含 `_restore_`，不得等于业务库。提前创建该库，仅授予该独立库的建表、触发器、增删查改和清理权限，不向业务进程提供 root 凭据。未配置时仍可备份、下载，恢复验证不可用；非空库绝不覆盖。开发 Compose 启用 `log_bin_trust_function_creators=1`，使仅获验证库 `TRIGGER` 权限的账号能创建只追加复核触发器；现有 MySQL 8.4 开发容器可由数据库管理员执行 `SET PERSIST log_bin_trust_function_creators=1`。生产环境须由部署人员按其日志和触发器策略配置，不能以给应用 root 权限替代。

## 人工恢复

先部署与备份结构版本一致的程序并创建新的专用空库。将原密钥、加密备份分别复制到受控位置；在终端临时设置 `RESTORE_DATABASE_URL` 为该空库连接串，保留原业务连接用于隔离校验，不把连接串写入命令参数或 Git。

在根目录、后端虚拟环境中执行：

```powershell
python scripts/restore_backup.py --archive D:\secure\snapshot.oibak --key D:\keys\backup.key --sha256 <清单中的完整摘要>
# 检查文件通过后实际导入并保留新库：
python scripts/restore_backup.py --archive D:\secure\snapshot.oibak --key D:\keys\backup.key --sha256 <清单中的完整摘要> --execute
```

恢复增加所有账号的登录版本，撤销旧 token；清除判题旧执行者，未完成任务重新排队；模型配置和密钥不从备份恢复，恢复库默认停用 AI。核对账户、训练、题目和判题后，再由部署人员切换业务连接。工具不自动切换或覆盖原库。

## 记录边界与限制

- AI 页面显示最近 100 条业务调用/规则降级记录；每次只记录最终调用，重试的完整费用不计入。用量缺失显示未知；部分已知数字仅作观察，账单以服务商为准。不保存提示词、源码或模型回复。
- 备份包含账户密码哈希及业务个人数据，文件加密后仍按私有数据管理。模型凭据、运行心跳、临时导入、任务维护队列及锁不导出。
- 当前为 MySQL 一致性快照的有界逻辑备份：单表十万行、总五十万行、原始数据 128 MB、加密文件 32 MB；超限明确失败，应改用数据库备份工具。维护任务执行上限三分钟，数据库结构版本不匹配拒绝恢复。
- 失效执行者可能留下未发布的加密孤立文件；它们不会成为可下载的成功备份，由部署人员核对清单后维护磁盘。本批未实现自动保留策略、跨主机容灾和全量生产部署。
