# 修改核验恢复验收

日期：2026-11-02。基线 `e9b3ddb`，交付至现有 MySQL 多语言分支与 PR #1。

## 触发问题与处理

答疑中原样重复提交后，后端正确拒绝将同代码算作修改；页面却仍提示重试同一记录，形成永久失败。实际问题涉及提交、代码编辑和答疑核验三个不同动作。

- 答疑过程中，源码和语言未变时说明原因，阻止按钮和键盘快捷键重复提交；普通执行仍可重新运行原代码。比较换行的方式与后端一致，保留其他原始字符与语言差异。
- 编辑器说明聊天消息不会自动替换待提交代码。
- 后端为旧提交、同代码、尚未完成判题分别返回可识别的错误原因，说明相关提交编号，权限和可信 AC 条件保持不变。
- 同代码错误提供“去修改代码”，滚动并聚焦编辑器；确定性拒绝不随聊天反复重发。网络问题和未完成判题保留重试，会话冲突提供重新开启提示。
- 新的真实修改可以继续核验，成功后清除旧错误；原记录、会话、草稿和测试证据保留。

## 后续与边界

该批次修复提交核验的恢复流程，没有改变判题结果或放宽“修改后真实执行”的要求。此前反映的 L3 固定闸门循环与“我贴出来了”被误判为索要代码仍待独立修复，不能因模型已开启而视为解决。
