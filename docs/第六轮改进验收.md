# 第六轮：程序输出与证据保存故障恢复

日期：2026-10-30。基线为第五轮 `2de3a23`。

## 已复现问题

真实 Docker 中运行 `std::cout.put(0)`，程序正常退出，但 NUL 输出无法写入 PostgreSQL JSONB。同步请求返回 500，提交保持 RUNNING、没有判定，重复请求返回 409 并命中卡住记录。临时独立数据库已确认该行为，未调用模型。

## 验收规则

1. 判题使用未经显示转义的原始输出和预期结果，保存证据时才转义不能存储的 NUL；不能通过清理输出把 WA 变成 AC。
2. 转义记录带 `escaped_fields` JSON Pointer 路径，界面说明不可见字符已转义。输入被转义时不宣称保存文本可直接复现，也不把它作为可执行反例。
3. 普通文本保持原样，证据摘要与实际持久化副本一致。编译、运行及嵌套日志均能安全保存。
4. 同步执行意外失败后先回滚，再尽力记录系统错误终态；对外返回固定 503，不泄露内部异常。正常取消、后台租约隔离与重试规则继续有效。
5. 成功后的产物清理异常不能覆盖可信判题结果；升级流水线版本，使旧版卡住缓存不阻塞新请求。
6. 独立 PostgreSQL 回归覆盖输出比较、转义存储及故障恢复，至少使用一次真实 Docker 验证最小程序。

本轮不把二进制日志展示等同于原始字节下载，不改变题包测试通过范围，也不自动篡改存量历史结果。

## 实施与验证

证据保存使用递归副本，NUL 显示为字面量 `\u0000`，摘要基于实际保存副本计算；原始运行结果和题包数据不被修改。输入转义时禁止将其作可执行反例。同步意外异常回滚后记录 `SANDBOX_ERROR`，已完成结果受保护；后台异常继续由工作器处理，成功后的清理错误只记录安全日志。流水线从 `v4` 升到 `v5`，不复用旧版卡住缓存。
