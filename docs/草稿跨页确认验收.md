# 草稿跨页确认验收

日期：2026-11-03；基线 `cd6339b`。本批只修改浏览器草稿确认协议，不改教学接口、数据库结构或外部模型开关。

## 实际问题

原协议先读共享草稿，比较编号后删除同一个存储键。两个标签页之间这两步并非事务：旧页读到自己的草稿后，新页恰好保存了新问题，旧页随后删除共享键，就会把新问题一起删掉。此前“新问题在整个确认操作之前写入”的用例无法覆盖这个交错。

独立复现使用基线 Git blob 运行相同场景：旧协议的新问题恢复结果为空；修复后仍为新页输入。未使用业务账号或真实数据库。

## 修复

每个问题版本保存独立的已确认标记。发送成功只确认该编号，不读取、删除或改写共享的当前草稿指针。读取时，当前编号若已确认就不再作为未发问题恢复；较新的编号仍可读取，迟到的旧确认不会复活已经发送的新问题。

保留原草稿格式和非 UUID 旧编号，读取不执行写入式“迁移”，避免旧读取快照覆盖另一个页面的新输入。UUID 大小写统一识别，确认标记仍按账号与提交隔离。存储不可用时不阻断输入和发送。

本机保留最后一次草稿记录与按编号的确认标记；已确认的内容不会再次恢复为待发问题，后续编辑替换当前正文。本批没有提供浏览器缓存保留策略。

## 验证

- 前端 **62 项**通过，TypeScript 与生产构建通过。
- 新回归覆盖“读取旧值期间另页写入”、旧快照与迟到确认、新问题已发送后再来旧确认、旧格式读取并发、账号/提交隔离与损坏缓存。
- 真实浏览器两个独立标签页使用单独测试地址和原生 localStorage：旧页保存问题，新页写入新问题，旧页确认后新内容仍在；新问题确认后刷新为空，再确认旧问题也不复活。
- 浏览器页与 5298 临时服务已清理；没有操作业务数据或付费模型。项目页面和现有模型配置保留，原目录及 `scripts/word_import/` 未改。

## 下一项已确认缺口

后端答疑消息接口当前只有正文，没有请求回执。服务端已提交回复而客户端响应丢失时，再次发送会新增消息并可能再次调用模型；会话锁只能串行，不能识别重放。本批的本机确认保护不等同于网络请求幂等。

后续应使用稳定请求编号、与消息同事务保存的服务端回执，以及重放时的权威历史恢复；不同编号的相同“不会”仍须正常继续讲解。实施时需要覆盖对象归属、并发重复、内容冲突、已核验状态和旧加密备份兼容，不能按正文简单去重。
