# 信息学竞赛错题诊断与答疑系统

把一次代码提交转成可检查的编译与运行证据，再引导学生修改、重新提交并验证结果。

本轮以核心可靠性为先，需求与验收以 [改进需求基线](docs/改进需求基线.md) 为准。其他设计、实验和论文文档保留为历史材料，其中的目标指标不代表真实教学效果。

## 当前实现

- FastAPI 后端、React/TypeScript 前端及 PostgreSQL 持久化。
- C++17 编译运行、表层检查、分诊和证据保存；模型解释作为可选辅助。
- 公开样例通过标记为 `SAMPLE_PASS`，无测试标记为 `NO_TESTS`；只有当前正式题包测试全部通过才为 `AC`。
- 已接入两个自建题包，共 6 个正式测试点。测试通过仅表示通过当前版本测试，不能证明知识点掌握。
- 学生数据按账号隔离；教师只可查看非空同班学生，管理员可查看全部。
- 学生口头表示“AC”不结束答疑。修改后的同题提交须通过正式题包验证，才可结案；普通聊天不更新掌握度。
- 工作台支持代码草稿、历史继续、执行证据、答疑、修改重提和带认证的错题卡导出。
- 修改后的提交保存父版本，能回看同一修复链的代码与结果；重复请求复用执行任务。
- 教师可确认、修订或退回本班诊断，绑定原始证据并保留追加式审计；过期版本与自动重诊断不能覆盖人工审定。
- 工作台使用持久后台判题，刷新后恢复同一任务；工作器续租、过期接管和有限重试均有数据库记录。同步 API 保留兼容。
- 学生可取消自己的排队或执行任务，再提交新版本；教师可查看授权范围内的队列积压、租约与失败记录。

## 本地启动

需要 Python 3.11+、Node.js 22+、pnpm 11 和运行中的 Docker Desktop。以下为 Windows PowerShell 命令。

在仓库根目录准备本地配置，再启动后端；`.env` 中填写本地密钥：

```powershell
if (-not (Test-Path .env)) { Copy-Item .env.example .env }
.\scripts\dev.ps1
```

脚本会启动开发基础设施、初始化 Python 环境、执行数据库迁移并启动 API。已有环境升级后也须执行迁移并重启旧进程。

可先运行 `scripts/dev.ps1 -CheckOnly` 检查启动参数；`-DisableLlm` 关闭本次服务的外部模型调用，`-SkipInstall` 跳过已完成的依赖安装。脚本保留环境与 `.env` 配置，依赖或迁移失败时停止启动。

另开终端，在仓库根目录导入自建题包：

```powershell
backend\.venv\Scripts\python.exe scripts\import_packages.py --check
backend\.venv\Scripts\python.exe scripts\prepare_demo.py
```

`prepare_demo.py` 准备账号和自建题包，不调用模型或自动生成学生提交。账号使用说明见登录页；演示密码仅用于本机。`teacher01` 对应“初一 1 班”，可查看同班学生；已有非空班级和密码不会被覆盖。

启动前端：

```powershell
cd web
pnpm install --frozen-lockfile
pnpm dev
```

前端地址为 http://127.0.0.1:5173，API 文档为 http://127.0.0.1:8000/docs。首次无模型配置时，确定性检查和执行证据仍可使用；不能定位的问题保留未知。

## 验证

在 `backend/` 激活 `.venv` 后运行：

```powershell
ruff check .
pytest -q
```

设置 `TEST_DATABASE_URL` 后可执行真实 PostgreSQL 接口回归；数据库名称必须包含 `test`，先以该连接执行 `alembic upgrade head`。测试使用事务回滚，不应指向业务数据库。额外设置 `RUN_DOCKER_TESTS=1`，可执行真实 C++ 错解、修改和答疑核验场景，需要本地 `oi-judge:dev` 镜像。

第七轮本机结果：后端 **380 项测试通过**，包括独立 PostgreSQL、取消与完成竞争、租约过期与旧执行者隔离、真实 Docker 判题、输入边界、空字节输出及学生退出码；Ruff 通过。`web/` 下 `pnpm test` 的 **28 项测试通过**，`pnpm build` 通过。学生与教师完整流程见各轮验收记录。验收时明确关闭外部模型，模型质量仍需单独评估。

CI 会运行后端静态检查、迁移、PostgreSQL 接口测试、全部跟踪文件的密钥扫描、工具检查、前端测试和构建；真实 Docker 判题是显式启用的本地回归。更多范围与限制见 [第二轮改进验收](docs/第二轮改进验收.md)、[第三轮改进验收](docs/第三轮改进验收.md) 与 [第四轮改进验收](docs/第四轮改进验收.md)。

## 后台任务

前端提交携带 `Prefer: respond-async`。`202` 表示已接受任务，通过响应中的 `Location` 查询排队、运行或完成状态，不代表通过测试。失败任务可由本人通过 `POST /api/v1/submissions/{id}/retry` 在次数上限内重试。

排队或执行中的持久任务可由本人或管理员通过 `POST /api/v1/submissions/{id}/cancel` 取消；重复取消幂等，完成结果不可覆盖。取消会撤销原执行者的写入权，保留代码与版本链。重新提交创建新任务；旧同步活动记录不会阻塞新后台请求。教师与管理员通过 `GET /api/v1/coach/judging` 查看授权范围的状态摘要；租约记录不能证明工作器在线。

API 默认内嵌工作器。需要分开运行时，API 设置 `JUDGE_WORKER_ENABLED=false`，另在 `backend/` 的虚拟环境中运行 `python -m app.worker`。多个工作器由 PostgreSQL 锁与租约协调；默认最多 3 次自动尝试及 2 轮人工重试。关闭工作器时任务保留排队，不会伪装为完成。

## 目录

- `backend/app/`：接口、业务服务、诊断、答疑与判题。
- `backend/tests/`、`backend/migrations/`：测试与数据库迁移。
- `web/src/`：学生工作台和教师查看界面。
- `problems/PTV-*/`：自建题包、标准程序和输入输出。
- `deploy/`、`scripts/`、`tools/`：部署、导入、评测和独立工具。
- `docs/`、`eval/`：设计、历史实验与评测材料。

## 配置与已知限制

仅提交无真实密钥的 `.env.example`。`.env`、私钥、运行目录和构建产物均在忽略规则内；题面、标签及评测数据随仓库公开。上传前可运行 `backend\.venv\Scripts\python.exe tools\check_secrets.py` 检查 Git 暂存内容，`--all` 检查全部跟踪文件；检查只报告路径与类型。

演示账号仅在 `APP_ENV=dev` 创建及展示。其他环境启动时须配置足够长度的 JWT 密钥并关闭调试；不要把已有演示库直接当作正式账号库。

同一浏览器的另一标签页切换账号后，旧页会停止操作并保留原账号草稿，重新登录即可继续。API 对象编号要求正整数且不超过数据库 `BigInt` 上限；JSON 正文不接受字符串、布尔值或小数代替编号。
